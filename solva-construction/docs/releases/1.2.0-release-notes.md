# Release 1.2.0 Notes

Release 1.2.0 moves the scheduler from private-beta mechanics toward a more credible construction planning product.

## Highlights

- Added the built-in `Construction Starter Schedule` template with construction sections, procurement, delivery, internal work, inspections, handover, starter comments, and dependency links.
- Activated Settings with Workdays-only scheduling and clear SQLite/browser/localStorage storage guidance.
- Enforced Inspection tasks as zero-duration same-day milestones through schedule-store normalization.
- Added safer destructive flows for task and people deletion.
- Clarified snapshot restore copy so users know restoring overwrites the active saved schedule.
- Added schedule-table polish: inline task type editing, `Attention` filter, clickable `Waiting On` dependency details, and design-system cleanup.
- Removed the non-persistent sidebar image upload affordance from release builds.
- Clarified dependency wording for same-day finish-to-start links and warned that setting `Delayed` can affect linked following tasks.

## Verification

- `npm run test`
- `npm run build`
- `npm run release:alpha`
- `npm run release:manifest:github -- --notes "Release 1.2.0 - construction starter schedule and release polish"`

## Notes

- Template data remains local browser/app preference seed data, while projects, schedules, snapshots, and people use SQLite in the installed Tauri app.
- Confirm-and-override for dependency-violating date edits remains deferred; 1.2 keeps blocked-edit guidance and current snap/block behavior.
