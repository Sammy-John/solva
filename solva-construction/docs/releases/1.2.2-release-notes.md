# Release 1.2.2 Notes

Release 1.2.2 focuses on the People directory upgrade, safer project assignment behavior, and migration protection for existing worksheets.

## Highlights

- Added a top-level People section on the entry page for managing a master directory of internal people and suppliers.
- Master People data is stored in SQLite in the installed app, with browser/localStorage fallback for development mode.
- New projects can select active project people from the master directory using checkboxes.
- People added during project setup are saved to the master directory and selected for the new project.
- Project People removal now deactivates people for future task assignment instead of deleting them from existing tasks.
- Inactive or archived people remain visible on existing task assignments so completed and historical work keeps its names.
- Assignment dropdowns now prefer active project people while still showing already-assigned inactive people where needed.
- Added a legacy People upgrade warning and approval dialog with snapshot-first guidance.
- Legacy upgrade handling is idempotent and does not silently rewrite existing project People data on load.
- Updated People-related UI styling across the entry page, project People modal, schedule table, and task detail panel.

## Verification

- `npm run test`
- `npm run build`
- `npm run release:version:check`
- `cargo check`

## Notes

- Project schedules and snapshots continue to save project People state alongside tasks, sections, and dependencies.
- Snapshot restore restores the project People state included in that snapshot. The master directory remains workspace-level data; use the database backup created before app updates for full workspace rollback.
- The build currently completes with Vite's standard large chunk warning from the 1.2.1 Excel export dependency.
